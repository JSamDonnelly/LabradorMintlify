Labrador is a browser-based accessibility testing platform built for accessibility consultants and teams. It takes a manual hybrid approach: guided manual testing does the real work, with automated axe-core scans clearing the machine-detectable issues out of the way first. Instead of cobbling together spreadsheets and templates, you run your audits inside a structured interface that walks you through every applicable WCAG criterion, helps you document issues with precision, and generates professional, client-ready reports in a few clicks. Everything happens in your browser at [testwithlabrador.com](https://www.testwithlabrador.com), no software to install, no configuration required.

## How Labrador works

<Steps>
  <Step title="Create an account">
    Sign up at [testwithlabrador.com](https://www.testwithlabrador.com/signup), the Free plan requires no credit card.
  </Step>
  <Step title="Create a project">
    Choose a testing methodology (**WCAG 2.2 AA Testing** or **VPAT® 2.5 – WCAG 2.2**) and give your project a name.
  </Step>
  <Step title="Add pages, components, and user journeys">
    List the URLs, UI components, and user journeys you want to audit. Labrador keeps results for each one separate.
  </Step>
  <Step title="Work through the criteria">
    Evaluate each WCAG criterion, log any failures with evidence, and track remediation progress.
  </Step>
  <Step title="Export and share">
    Generate an interactive HTML report, VPAT DOCX, or CSV, ready to send to clients or developers.
  </Step>
</Steps>

## Core features

### Guided WCAG criterion testing

Work through every applicable WCAG 2.1 and 2.2 success criterion with built-in Testing Tips, plain-language criterion summaries, and a **Why This Matters** section that explains the real-world impact of each criterion. Complex criteria, such as 1.3.1 Info and Relationships, break down into expandable sub-criteria (Headings, Lists, Tables, and more) so you can mark each element independently rather than making a single sweeping judgment.

### Page, component, and user journey management

Organise your work the way it makes sense for your project. Add individual pages, UI components, and multi-step user journeys to a project, test each one against the full WCAG checklist, and track progress at a glance. The Criteria Overview for each item shows a live progress bar and a status tally, Pass, Fail, N/A, and Untested, broken down by Level A and Level AA.

### Issue documentation

When a criterion fails, log the specific issue directly underneath it. Each issue supports:

- A written description and remediation guidance
- **Severity levels:** Advisory, Minor, Moderate, Serious, and Critical
- **Remediation status:** Reported, In Progress, Fixed for Retesting, or Closed
- Media attachments, screenshots and video recordings up to 100 MB per upload

All issue data is auto-saved as you type.

### Audit versioning

Every project starts at **v1.0**. When your client returns with fixes to verify, create a retest version (v1.0 → v1.1): Labrador carries your pages, criterion statuses, and logged issues forward so you can check each finding without re-documenting it. When you need a fresh top-to-bottom evaluation of the same site, start a new major audit version (v1.x → v2.0), either with the existing page list or as a completely blank slate.

### A manual hybrid approach

Labrador pairs guided manual testing with automated [axe-core](https://github.com/dequelabs/axe-core) scans, run straight from the Criteria Overview through the Labrador Chrome extension. The scan gets the machine-detectable issues out of the way first: findings arrive mapped to their WCAG criteria, you review each one before it is imported, and every accepted result becomes an issue under the right criterion with the axe rule and affected element pre-filled. That leaves your effort for the roughly 70 percent of issues only a human can find.

### Jira Cloud integration

On any paid plan, connect a project to your Jira Cloud board and every issue you log is created in Jira automatically, no copy-paste handoff. Status and priority changes sync in both directions, so closing a ticket in Jira marks it as Closed in Labrador and vice versa. On the Free plan, use the Jira-ready CSV export instead.

### Professional exports

Generate reports your clients and stakeholders can actually use:

- **Interactive HTML**, includes an executive summary, detailed findings, embedded screenshots and videos, clickable WCAG criterion links, and a "Show Failures Only" toggle for developers
- **VPAT® 2.5 / DOCX**, a fully editable Word document following the VPAT template, available for projects created with the VPAT methodology
- **CSV**, a detailed flat export for use in Excel, Google Sheets, or custom workflows
- **Jira-ready CSV**, formatted for direct import into Jira, available on all plans

### Team collaboration

Invite colleagues to a project and assign pages or criteria between team members. Role-based permissions let you control exactly what each person can do:

- **View-only**, for clients and stakeholders who need to review findings without making changes
- **Developer**, can update remediation status and add comments only
- **Editor**, full testing and documentation access

### AI-assisted remediation

The **Labrador AI Accessibility Assistant** Chrome extension lets you capture the HTML of a specific element directly from a live page. Once you've written an issue description, click **Generate Recommendation** and select the problem element, Labrador drafts developer-ready remediation guidance based on your description, the captured HTML, and the WCAG criterion under review. The suggestion is editable before it becomes part of your exported report. The feature is powered by Claude Opus and is currently in beta.

## Standards coverage

<Note>
  Labrador supports **WCAG 2.1 and 2.2** at conformance Levels **A**, **AA**, and **AAA**. All plans include the full testing toolkit for both versions. For organisations that need formal accessibility conformance documentation, projects created with the VPAT methodology produce a **VPAT® 2.5 (WCAG version)** report, suitable for government procurement and enterprise compliance requirements.
</Note>
