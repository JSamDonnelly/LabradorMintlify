The HTML export produces an interactive report that your clients and stakeholders can open in any modern browser, no account, no login, and no special software required. Findings, and most screenshots and videos, are embedded directly in the file, so you can share it by email or file transfer. Very large media files are linked instead of embedded; see [Large screenshots and videos](#large-screenshots-and-videos) below.

## What's included in an HTML report

An HTML report contains everything your client needs to understand the audit findings and hand remediation work to their development team.

<Accordion title="Testing information and overview">
  The report opens with **Testing information**, which always shows the WCAG version tested against and the auditor's name, followed by an **Overview** of the results. The audit version and the date the report was generated appear in the header. These sections give stakeholders a high-level view before they read the detailed findings.
</Accordion>

<Accordion title="Issues">
  The **Issues** section lists every logged issue with its WCAG criterion, severity, and remediation status, along with your issue description, the remediation guidance you wrote, and any attached screenshots or videos.

  Every issue heading begins with that issue's reference, for example **LAB-39**, the same identifier the issue carries in your CSV exports. Quote the reference when you discuss an issue with a developer and it points at that issue and no other.
</Accordion>

<Accordion title="Best-practice recommendations">
  Issues logged as [best-practice recommendations](/projects/logging-issues#best-practice-recommendations) are not conformance failures, so they are not listed among the issues. When a project has any, the report ends with a **Best-practice recommendations** section, linked from the report's contents. Each recommendation shows its page or component, severity, any related criterion, description, remediation guidance, and attached screenshots or videos.
</Accordion>

<Accordion title="User journeys">
  If the project has user journeys, the report includes a **User journeys** section.
</Accordion>

<Accordion title="Pages and components">
  The **Pages & components** section shows conformance and failing criteria for each page. Expand a page to review every criterion evaluated on it.
</Accordion>

<Accordion title="Screenshots and videos">
  Screenshots and videos attached to an issue are embedded directly in the HTML file, so recipients see the evidence without an internet connection. Very large files are the exception: see [Large screenshots and videos](#large-screenshots-and-videos).
</Accordion>

<Accordion title="Clickable WCAG Criterion Links">
  Every criterion number in the report is a clickable link. Clicking a criterion number, for example, **1.1.1 Non-text Content**, opens the official W3C WCAG documentation for that criterion in a new tab, so developers can read the full normative definition without leaving the report.
</Accordion>

<Accordion title="Severity and Remediation Status">
  Each issue is labelled with its severity (Advisory, Minor, Moderate, Serious, or Critical) and its remediation status (Reported, In Progress, Fixed for Retesting, or Closed), giving developers a clear picture of what to prioritise and what has already been addressed.
</Accordion>

<Accordion title="Remediation Guidance">
  Where you added remediation help to an issue, including any AI-generated recommendations you reviewed and kept, that guidance appears in full alongside the issue description. Developers can read the fix recommendation directly from the report without opening Labrador.
</Accordion>

<Accordion title="Section navigation">
  An **On this page** list of links lets readers jump between the sections of the report without scrolling through the entire document.
</Accordion>

## Interactive features in the report

Labrador HTML reports are not static documents. They include interactive controls that help readers focus on what matters to them.

- **Severity filter**, buttons above the issues list show how many issues there are at each severity. Select one to show only those issues, or **All** to show everything.
- **Sort by page**, groups the issues list by page.
- **Expandable page details**, each page in **Pages & components** expands to show every criterion evaluated on it.
- **Print / Save PDF**, opens your browser's print dialog, where you can print the report or save it as a PDF.
- **Download HTML**, saves the report as a `.html` file.

## Generating an HTML report

<Steps>
  <Step title="Open your project">
    Go to the Projects dashboard and open the project whose results you want to export.
  </Step>
  <Step title="Click Export">
    In the project toolbar, click the **Export** dropdown.
  </Step>
  <Step title="Select HTML">
    Choose **HTML** from the dropdown menu.
  </Step>
  <Step title="Review the report">
    The report opens in a new browser tab. Read it through before sending.
  </Step>
  <Step title="Download and share the report">
    Select **Download HTML** at the top of the report to save it as a `.html` file. Share it with clients by attaching the file to an email or uploading it to a shared drive. It opens in any modern browser: Chrome, Firefox, Safari, or Edge.
  </Step>
</Steps>

<Tip>
  HTML reports are the recommended format for client delivery. They require no special software to open and give your clients an interactive experience rather than a static document. When in doubt, use HTML.
</Tip>

## Large screenshots and videos

To keep the report a manageable size, Labrador embeds a screenshot or video only when the file is 1.5 MB or smaller, and stops embedding once the embedded media in one report adds up to 80 MB. Anything over those limits is loaded from Labrador storage instead.

When a report contains linked media, it says so in a note. Two things follow:

- **Linked media needs an internet connection.** Embedded media still works offline.
- **The links expire after one year.** If a client needs the evidence for longer, export the report again to get fresh links.
